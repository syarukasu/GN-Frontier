GN Frontier 日替わり任務（r34・調達品の拡充と数量連動）

編集先: data/gnfrontier/daily_missions/catalog.json

実行処理はGN Frontier専用MODの1本に統合。第三者MODのJAR変更なし。

納品依頼は deliveries 内の共通部品から生成する。
・items: 38品目。品名・item・必要ならgun_id・数量候補counts・単位unit・単価unit_reward・基本料base_reward。
・requesters: 9種類の依頼主。表示名labelと、報酬評価の所属merchant。
・purposes: 24用途。表示名label・事情reason・適合する品目items・適合する依頼主requesters。
・titles / openings / circumstances / instructions / endings: 題名4、冒頭8、不足の事情8、納品案内6、結び8の共有文。
・sizes: [1,2,3]。用途の候補品が少ない場合は、選べる品目数の範囲に収める。

用途→その用途の依頼主→1〜3種類の候補品目→数量を抽選し、要求個数に応じて品目数を減らしてから、報酬と文章を確定する。
品目の重複はなく、同日の別依頼にも同じ物資を重ねない。全アイテムの無差別抽選ではない。
題名と共通文で使える置換は {purpose} と {requester}。用途のlabel/reasonには置換を使わない。
納品物と必要数はPDAで品目ごとに表示する。必要数の不足を別の物資の余剰で補うことはできない。
報酬は各品目の（base_reward + unit_reward × 個数）の合計。所属評価の報酬は依頼1件につき5。
全品目を揃えて一括納品する。一つでも不足すれば、在庫・報酬・受領済み状態は変更しない。
装備・副手・無効ホットバーは納品対象外。通常素材は独自NBT付きの品を消費しない。指定銃はGunIdも照合する。

日替わりは最大3件。少なくとも1枠を納品、1枠を地上戦、残る1枠は75%で納品、25%で戦闘から抽選する。
候補枯渇時は依頼数が減る。1枠192候補まで試し、巨大な全組み合わせの展開は行わない。
履歴は1人10万件まで保存し、上限到達時は自動再利用せず発行を止める。

固定ID（テンプレート・文章・対象）は配布後に変更・再利用しない。文章の訂正は同じIDで行う。新しい選択肢には新規IDを付ける。
プレイヤーごとに発行した組み合わせと本文の履歴を保存する。既出の組み合わせは再出題しない。直近の対象も可能な範囲で避ける。使い切った場合は自動で再利用せず、依頼が減るか表示されなくなる。
同じ品そのものは別の文章・数量で再登場する。すべての納品品目の永久禁止ではない。
日替わりはワールドの経過24,000tickごと。受注後も日付更新で失効する。リログ・画面再表示では引き直さない。
生成済み任務の品目・個数・本文・報酬は保存され、編集は次の新規依頼から適用する。再起動またはデータ再読み込みで定義を更新できる。
旧版ですでに出ていた当日の依頼はその日まで維持し、翌日から新方式へ移行する。旧版が記録していない過去の履歴は復元できない。
闇商人の一度限りの専用任務8件は merchant_quests/black_market.json で別に管理する。

存在しない品目・不明な参照・重複・範囲外数量・未対応の置換は読み込み時に拒否する。
戦闘は従来の templates を使用する。HUNT=モブ、SOLDIER=交戦中の敵兵、SHIP=敵船舶、HELICOPTER=敵ヘリ。
schema 2ではtemplates内の旧DELIVERYは新規抽選に使わず、旧仕様の互換性検証用に残している。

電子スクラップ16個=$200は動画の確認値に合わせた。フィルター10個=$450は動画の一般フィルター依頼を数量・報酬の基準にしたが、現行品はパックの交換フィルターであり、原動画の品目IDとの一致は未確定。その他の文言・数量・報酬は再現用の補完。旧式の制御基板8枚=$300も映像では確認できるが、原品目IDは未確定で、高度な回路と同一扱いしない。商人がノア計画を知る文言は含めない。

調達方針（r34）
電子・電気部品11、工業資材10、医療・防護・補給9、旧式銃8の計38品目。糸・革・丸石・板材等の序盤素材は戻していない。追加品と用途は動画の調達難度に寄せた補完で、全品を映像で確認した意味ではない。
各itemsのbundle_limits.max_for_threeは3品依頼に含められる最大個数、max_for_twoは2品依頼に含められる最大個数。後者を超えれば必ず単品。銃1丁は最大2品、2丁以上は単品。個数は切り下げず、多量の品を残して同時要求の品数を減らす。削除した品の代金を報酬に含めない。
3品の候補では少量、2品では中量以下の数量候補を優先して抽選する。対応する数量候補がない品は通常の数量抽選を行い、その結果に合わせて品目数を減らす。
例：電子スクラップ16個は単品。電子スクラップ4個・回路基板2枚・電池2個は3品で成立する。具体的な組み合わせは用途内の抽選。
旧定義でbundle_limitsがない品は従来どおり最大3品。発行済みの任務は改変せず、データ更新後に生成する依頼から適用する。専用任務8件は変更していない。
